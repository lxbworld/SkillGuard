# SkillGuard Phase 0 corpus report

**Status: not yet run on a real corpus.** This placeholder exists so the file
named in `docs/PHASE0_CORPUS_STUDY.md` §5 (D7) is not a surprise later.

The report is generated, not written by hand:

```bash
skillguard corpus index <checkout> --layer L3 --out research/corpus-manifest.jsonl
skillguard corpus scan  --manifest research/corpus-manifest.jsonl \
                       --tree <checkout> --out research/raw-findings.jsonl
skillguard corpus report --findings research/raw-findings.jsonl \
                         --out docs/CORPUS_REPORT.md
```

The generator refuses to omit the honest declarations in
`docs/PHASE0_CORPUS_STUDY.md` §5.1, and reports failed entries in the
denominators table rather than folding them into the denominator.

## Why it is empty

Only GitHub code search (L3) is cleared for bulk collection. Every registry
source is `unclear` and awaiting a reply — see `research/TERMS-REVIEW.md` and
`research/DISCLOSURE.md`. The study can proceed on L3 alone, at the cost of
install-count stratification.

So the correct state for this file today is: the pipeline works, the protocol is
pre-registered, and no number is published until there is a corpus behind it.
`tests/corpus.rs` runs the whole pipeline on a three-skill fixture to prove the
mechanics; it is not evidence about the ecosystem.

`corpus reproduce <manifest>` re-derives every digest and fails the run if the
tree has drifted, which is the check that makes the eventual numbers citable.

`corpus report --gold <GOLD.jsonl>` computes per-rule precision and recall from
hand labels (`{source_id, rule, verdict: tp|fp|fn}`) and reports the G4 gate. It
refuses to micro-average, and a rule with no `fn` labels shows `n/a` for recall
rather than a perfect score — an unmeasured number is not a good one.
